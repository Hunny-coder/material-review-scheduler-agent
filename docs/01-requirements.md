# 需求与成功标准

用户为内容团队的运营、审核和排期负责人。目标是发现待处理素材，说明资料与规则风险，形成无冲突、可确认的草稿。系统不连接真实发布。

输入包括素材 ID、渠道、账号、带时区的发布时间要求、替代建议搜索窗口、合成素材、规则和已有排期。工具覆盖读取、补查、规则检查、时段查询、提案登记和草稿保存。

每项输出包括审核状态、风险原因、缺失项、建议时段、生效时段、原始要求、确认状态、待确认事项、草稿保存事实及执行停止原因。状态由工具事实组装，不采用模型自述作为成功依据。

| 要求 | 成功标准 | 实现与验证 |
| --- | --- | --- |
| 正常排期 | 完整资料、规则通过、时段可用则保存草稿 | normal 场景 |
| 素材信息缺失 | 先补查，仍缺失则请求补充且不保存 | missing / recoverable |
| 规则风险 | 返回规则、字段和证据，阻断或请求人工审核 | risk / manual-review |
| 时段冲突 | 查询替代建议，硬要求变化须确认 | conflict / shifted-conflict |
| 重复提交 | 同请求同素材只有一个逻辑草稿，回执重放 | duplicate / 并发测试 |
| 保存失败 | 提交前失败回滚，无虚假成功回执 | failure / 事务测试 |

`exact` 必须满足原时间；`window` 和 `preferred` 只能在明确授权的窗口内生效。替代搜索窗口只允许寻找建议。M01 原要求 18:00、冲突后建议 19:00 时，必须 `pending` 且 `effective_slot=null`，未经确认不能把 19:00 当作有效排期。

确认绑定草稿、提案版本、随机 token 和素材/规则/排期证据；保存和确认时重新检查冲突。相同请求 ID、修订号但输入不同必须拒绝。

额外验收包括：更换占用时段后复跑、旧确认失效、批量互相占用、无可用时段、调用上限、未知事务结果、非法模型动作和真实模型不可用。全部具体证据见 [评估文档](03-evaluation.md)。

范围选择为 Python CLI、单 Agent、LangChain 1.x + LangGraph 1.x、本地 JSON 与 SQLite。界面、部署、多 Agent 和生产 Runtime 均未安排。百炼 Qwen3.8-Max 的两条真实循环及六项验收已完成，详见 [真实模型报告](06-qwen-evaluation.md)。
